# 歌声音域推定ツール 設計案

MV 等の音源から、楽曲ごとの以下 4 値を自動推定するツールの設計。

| 出力 | 備考 |
|---|---|
| **地声最高音** | 本命。歌手の限界に近い |
| **地声最低音** | 実用上ほぼ「その曲の最低音」 |
| **裏声最高音** | 本命 |
| **裏声最低音** | 出現が稀。検出できなければ `null` |

派生指標として音域幅（地声・裏声・全体）も併せて出力する。

---

## 0. 前提と注意

- YouTube からの音声ダウンロードは YouTube 利用規約に抵触する可能性がある。開発・評価は手持ち音源／購入音源／CC ライセンス音源を主軸にし、URL 入力は「ローカルファイル入力の一形態」として実装しておくのが安全（`ingest` を差し替え可能にする）。
- 音域まとめサイトのラベル収集も、robots.txt・利用規約の確認とレート制限（1req/2s 程度、User-Agent 明示、ローカルキャッシュ）が前提。取得したラベルは**手元の学習用途に限定**し再配布しない。

## 1. いちばん重要な発想の転換

### 1-1. 「全フレームのレジスター分類」は要らない

素直に考えると「歌声の全区間を地声/裏声に分類する器」を作りたくなるが、**欲しい出力は曲ごとに数個の数字だけ**。

つまり実際に判定が必要なのは、**その曲で検出された音のうち上位 10〜20 ノートと下位 10〜20 ノート**だけ。
これが効いてくる：

- 人手ラベリング量が 1/50 以下になる（1 曲 40 ノート × 100 曲 = 4000 サンプルで十分な規模になる）
- 能動学習（判定が曖昧な候補ノートだけ人に聞かせる）が自然に成立する
- 推論も軽い（分離と F0 抽出が支配的で、分類器は誤差レベル）

### 1-2. サイトのラベルは「曲単位の弱ラベル」

`地声最高音 = hiA` は「この曲の地声ノート集合の max が A4」という**集合レベルの制約**であって、
どのノートが地声かは教えてくれない。これは **Multiple Instance Learning (MIL)** そのもの。

ただし制約から**タダで擬似ラベルが取れる**のが美味しい。**最低音ラベルを足すと制約が倍になり、
特に「下限を下回るノート＝検出ミス」という強力なクリーニング信号が手に入る**：

| 条件 | 導かれること | 確度 |
|---|---|---|
| ピッチ > 裏声最高音 + 1半音 | 検出ミス／ハモリ／ノイズ | **高** |
| ピッチ < 全体最低音 - 1半音 | 検出ミス（**ほぼベース/キックの漏れ込み**） | **高** |
| ピッチ > 地声最高音 + 1半音 | 地声ではない（＝裏声 or 検出ミス） | **高** |
| ピッチ < 地声最低音 - 1半音 | 地声ではない | **高** |
| 地声最高音 付近で最頻・最長 | 地声の陽性例 | 中 |
| 地声最低音 付近で最頻・最長 | 地声の陽性例 | 中 |

→ **上下限制約が「負例の自動生成器」として働く**。ここが弱教師で回せる根拠。
2 行目は §4-2 の低域ブリード問題に直接効く教師信号で、**最低音ラベルを入れること自体が
低音検出の精度を上げる**という好循環になる。

### 1-3. `max` / `min` は壊れやすい統計量

1 フレームの誤検出で答えが変わる。高音側はハモリ・シャウト・ノイズ、低音側はベース漏れ・
語尾の落ち込み・ボーカルフライが全部効く。対策として **素の `max` / `min` を使わない**：

> 「持続 ≥150ms、ピッチ安定（cents 標準偏差 < 50、傾斜 < 200 cents/s）、有声確信度 ≥ 閾値、
> かつ曲中 2 回以上出現」を満たすノートの最高値／最低値

さらに保険で 0.5 / 99.5 パーセンタイルも併記して乖離を監視する。これだけでサイトラベルとの一致率がかなり上がるはず。

## 2. パイプライン

```
[入力] mp3/wav (or URL)
   │
   ├─ 1. 音源分離           Demucs (htdemucs, 4stem) or BS-Roformer
   │      ├─ vocals          → 解析対象
   │      ├─ bass/drums      → 低域ブリード判定の参照に使う（捨てない）★
   │      └─ リード抽出      Mid/Side 処理でセンター成分強調（ハモリはサイドに広い）
   │
   ├─ 2. F0 推定（2パス）★
   │      ├─ 中高域          RMVPE（歌声に強い）/ torchcrepe
   │      ├─ 低域            長窓 pYIN（自己相関ベース、低域に強い）
   │      └─ 後処理          Viterbi 平滑化 + オクターブ誤り検出（高音は下、低音は上に飛ぶ）
   │
   ├─ 3. ノート化           半音量子化 → 安定区間セグメント化 → 各ノートの中央値 cents
   │      └─ フィルタ       最短長・安定度・傾斜・有声確信度・エネルギー（閾値は高低で別々に持つ）
   │
   ├─ 4. 候補選抜           ピッチ上位 N=20 + 下位 N=20 ノートのみ次段へ
   │
   ├─ 5. ノート種別分類 ★
   │      ├─ 声 / 非声       低域ブリード除去（bass stem 相互チェック + フォルマント有無）
   │      ├─ 通常 / フライ   ボーカルフライ（エッジボイス）を別タグに
   │      └─ 地声 / 裏声     レジスター分類  ★本体
   │
   └─ 6. 集約               ロバスト統計で 地声/裏声 の 最高音・最低音を確定
          [出力] JSON + 根拠（該当ノートの時刻・音声切り出し）
```

### オクターブ誤りの検出（地味だが致命的）

推定 F0 に対して以下をチェックする。**誤りの向きが音域で逆転する**点に注意：

- 高音（特に裏声）：1 オクターブ**下**に落ちやすい → `F0×2` に強いピークが無いか確認
- 低音：基音が弱く倍音を掴んで 1 オクターブ**上**に張り付きやすい → `F0/2` にピークが無いか確認
- 推定 F0 の位置にスペクトルピークが実在するかを常に確認する
- ノート内でのオクターブジャンプは平滑化で潰す

## 3. 地声 / 裏声の判別

### 3-1. 音響的な手がかり

音声科学的には modal（地声）と falsetto（裏声）は声帯の振動様式が違い、以下に現れる：

| 特徴量 | 裏声での傾向 | 実装 |
|---|---|---|
| **H1-H2**（第1・第2倍音の振幅差） | 大きい（開放商が高い） | 自前 or opensauce |
| **H1-A1 / H1-A3** | 大きい | 声道フィルタ補正付き |
| **スペクトル傾斜 / 高域エネルギー比** | 急峻（高域が薄い） | librosa |
| **シンガーズフォルマント帯 (2.5–3.5kHz)** | 弱い（ベルト声で強い） | 帯域エネルギー比 |
| **CPP（ケプストラルピーク顕著性）** | 低い（息成分が多い） | parselmouth |
| **HNR** | 低い | parselmouth |
| **ビブラート深さ・レート** | 浅くなりがち（個人差大） | F0 軌跡の FFT |
| **直前ノートからの跳躍幅・時間ギャップ** | 大きい（レジスターブレイク） | 文脈特徴 |
| **F0 の歌手内相対位置** | 高い | ★下記 |

### 3-2. 歌手内正規化がほぼ必須

男女・声種で絶対音高の意味が全く違う。A4 は男性なら裏声寄り、女性なら地声の常用域。
そこで **曲（＝歌手）ごとの F0 分布統計**（中央値、10/90 パーセンタイル）で正規化した相対ピッチを特徴に入れる。
これを入れるかどうかで精度がかなり変わるはず。

### 3-3. モデルの段階

| 版 | 手法 | 必要データ | 学習コスト |
|---|---|---|---|
| **v0** | ヒューリスティック（推定パッサージョ + スペクトル傾斜の閾値） | 0 | 0 |
| **v1** | 手設計特徴 + LightGBM | 数百ノート | 数秒 |
| **v2** | **凍結 SSL エンコーダ + 線形プローブ**（WavLM / HuBERT / MERT の中間層） | 数百ノート | 数分（GPU） |
| **v3** | log-mel パッチ CNN + 手設計特徴 concat、弱教師で全曲学習 | 数千曲 | 数十分〜 |

**個人 PC 前提なら v2 が最もコスパが良い。** 事前学習済みモデルは凍結して特徴抽出器として使うだけなので、
実際に学習するのは線形層 or 小さな MLP のみ。数百サンプルでも十分に立ち上がる。
v1 は解釈性が高く「何が効いているか」を見るのに有用なので、v1 と v2 は並走させて比較するのが良い。

なお **低音側ではレジスター分類器の出番は小さい**（ほぼ全部が地声）。低音側の精度を決めるのは
§4 の「声か否か」「フライか否か」の判定であって、地声/裏声の判別ではない。

### 3-4. 弱教師（MIL）の定式化 — v3 向け

曲 `s` のラベルを `c⁺_s, c⁻_s`（地声の最高・最低）, `f⁺_s, f⁻_s`（裏声の最高・最低）、
ノート `i` のピッチ `p_i`、裏声確率 `q_i` とする。微分可能な soft-max / soft-min（log-sum-exp, 温度 τ）で：

```
ĉ⁺_s =  LSE_τ(  p_i + λ·log(1 - q_i) )      # 地声 max
ĉ⁻_s = -LSE_τ( -p_i + λ·log(1 - q_i) )      # 地声 min
f̂⁺_s =  LSE_τ(  p_i + λ·log(q_i)     )      # 裏声 max
f̂⁻_s = -LSE_τ( -p_i + λ·log(q_i)     )      # 裏声 min

L = Σ_k Huber(推定_k - ラベル_k)                    # k ∈ {c⁺, c⁻, f⁺, f⁻}
  + α·Σ_i ReLU(p_i - max(c⁺_s, f⁺_s) - 1)           # 上限超過 = 検出ミス
  + α·Σ_i ReLU(min(c⁻_s, f⁻_s) - 1 - p_i)           # 下限未満 = 低域ブリード ★
```

第 3・4 項がノートのクリーニング項。ノートレベルのラベルなしに、曲レベルのラベルだけで
`q_i` と「そもそもこのノートは声か」を同時に学習できる。
`f⁻_s` は欠測が多いので、欠測時はその項をマスクする。

## 4. 低音側の固有課題（高音側の裏返しではない）

低音は高音とは**失敗のモードが根本的に違う**。ここを別扱いしないと低音の精度は出ない。

### 4-1. F0 推定が低域で構造的に弱い

- 65Hz（C2）の 1 周期は約 15ms。一般的な 25ms 窓では 2 周期しか入らず推定が不安定。窓を伸ばせば
  時間分解能が落ちる、というトレードオフが本質的にある。
- CREPE / RMVPE は学習データの分布上、低域で精度が落ちる。
- 対策：**2 パス F0 推定**。中高域は RMVPE、低域は長窓 pYIN（自己相関ベースで低域に強い）。
  両者が一致する区間だけ高信頼とし、不一致区間は候補から落とすか低信頼タグを付ける。

### 4-2. ベース／キックのブリードが本命の敵

Demucs の vocals stem には低域楽器の漏れ込みが残る。ハイパスで潰すと本物の低音まで消えるので使えない。

- **bass stem との相互チェックが最も効く。** Demucs は 4stem 出せるので、vocals 側で検出した低音 F0 が
  bass stem にも同時刻・同ピッチ（±50 cents）で存在すれば漏れ込みと判定して棄却する。
  分離モデルを 2stem ではなく 4stem で回す理由がここにある。
- **フォルマント構造の有無。** 人声には F1/F2 のフォルマントがあるがベースには無い。低域候補に
  フォルマント検出をかけて母音らしさを見る。
- SSL 埋め込みの線形プローブでも「声/非声」は容易に切れる。

### 4-3. ボーカルフライ / エッジボイス

最低音付近では声帯が不規則振動になり、F0 が定義しにくい・見かけ上半分になる。

- 検出：周期性の急落（HNR / CPP の低下）+ 極端に低い F0 + パルス間隔のばらつき増大
- サイトの「最低音」がフライを数えるかは規約次第で、しかも記事ごとにブレる。
  → **フライは別タグとして保存し、集約時に「含める／含めない」を切り替えられるようにする。**
  これをやらないと評価値が安定せず、モデルの改善が測れなくなる。

### 4-4. 語尾の落ち込み（フォール）

語尾でピッチが滑り落ちる部分を音として数えるか。通常サイトは数えない。

- ノート内のピッチ傾斜が大きい区間（例：> 200 cents/s）は「音」ではなく遷移として扱い、
  安定区間だけを候補にする。
- 同じロジックが高音側の「しゃくり」にも使えるので、共通の前処理として実装する。

### 4-5. SN 比が悪い

低音は音量が小さくミックスに埋もれる。有声確信度やエネルギーの閾値を高音側と共通にすると、
下げれば拾いすぎ・上げれば取りこぼす、のどちらかになる。
→ **閾値は高音側と低音側で別に持ち、別々にチューニングする。**

### 4-6. 裏声最低音は概念として弱い

裏声で低音を出すことは可能だが曲中に現れることは稀で、ラベルを持つサイトも少ない。

- 出力は optional（検出できなければ `null`）。無いことを「失敗」として扱わない。
- 学習上は極端なクラス不均衡になるので、無理に精度を追わない。
- 実用上は **地声最低音 = その曲の最低音** であることがほとんど。

### 4-7. 「最低音」は歌手の限界を表さない

最高音は歌手の限界に近いことが多いが、最低音は「その曲にたまたま低い音が無かった」だけのことが多い。
つまり **最低音のラベルは楽曲依存性が高い**。

- 曲単位の評価では問題ないが、**複数曲を集約して「歌手の音域」を出す場合は非対称に扱う**：
  最高音は少数曲でも意味があるが、最低音は曲数が少ないと過大評価（高すぎる値）になる。
- 集約時は曲数を添えて出し、少数曲の歌手の最低音は信頼度を下げる。

## 5. 教師データ戦略

推奨は **シード → 能動学習 → 弱教師スケール** の 3 段。

1. **シード（最重要・最初にやる）**
   自分で 30〜60 分ぶん、地声と裏声を音階で録音する。ラベルが完全に正しい唯一のデータで、
   特徴量が本当に効くかの検証に使える。ここで H1-H2 等が分離しないなら設計を疑うべき。
   **低音側はここでボーカルフライも意図的に録っておく**と、フライ検出の開発が一気に楽になる。
2. **能動学習ラベリング**
   §1-1 の通り、1 曲あたり上位 20 + 下位 20 ノートだけを人が聞いて
   `1=地声 / 2=裏声 / 3=フライ / 4=非声(楽器) / 5=判定不能` を押す UI を作る。
   1 曲 2〜3 分。50 曲で 2000 ノート。**ここが一番の投資対効果**。
   分類器の確信度が低いノートを優先提示すれば効率がさらに上がる。
3. **弱教師スケール**
   サイトのラベル（曲単位）で §3-4 の MIL 損失を回し、数千曲規模へ。

**公開データセット候補**（要現物確認、ライセンスも要確認）：
VocalSet（歌唱技法ラベル付き。belt / breathy / vocal fry 等がレジスター判別の代理になり得る）、
NUS-48E、OpenSinger、M4Singer、Opencpop。
ただしレジスターを直接ラベルしたデータセットは乏しいので、過度に期待しない方がよい。

## 6. ラベルの品質問題（無視すると評価が壊れる）

- **ミックスボイスの扱いがサイトごとに違う。** 地声に含めるサイト/含めないサイトがある。同一サイトでも記事によってブレる。
- **アドリブ・フェイク・シャウトの扱いが違う。** 「最高音」がサビの決め音を指すか一瞬の叫びを指すかが不定。
- **低音側はさらにブレる。** ボーカルフライ、語尾の落ち込み、囁き声を数えるかの規約が明示されていないことが多い。
- **ハモリ・コーラスが混入した記載**がある。
- **裏声最低音は欠測が普通。** 欠測とゼロを区別して扱う。
- 対策：
  - ソースを 1 サイトに固定して**規約を揃える**（複数サイト混在は最後にやる）
  - ±1 半音の許容で評価する
  - ノイズ耐性のある損失（Huber, ラベルスムージング）を使う
  - 学習前に整合性チェックで矛盾曲を弾く：
    `地声最低 ≤ 地声最高`、`裏声最低 ≤ 裏声最高`、`裏声最高 ≥ 地声最高`（大半の曲で成立）、
    音域幅が異常に広い/狭い曲（表記ミスの疑い）

## 7. 評価

- 主指標：半音単位の絶対誤差 MAE、および **±0 / ±1 / ±2 半音以内の一致率**を
  **4 値それぞれ独立に**算出する（平均してはいけない。低音側と高音側で難易度も失敗要因も違う）
- 副指標：音域幅の誤差（上下の誤差が同方向なら相殺されるので、幅の指標は別途見る価値がある）
- フライ含む／含まないの両方で低音側を評価し、どちらがサイト規約に近いかを実測で決める
- 必ずベースラインと比較する：
  - B0: 「全ノートの max = 裏声最高音、min = 地声最低音、パッサージョ推定値以下の max = 地声最高音」
  - B1: v0 ヒューリスティック
- 曲は **アーティスト単位で** train/valid/test 分割する（同一歌手のリークを防ぐ）
- エラー分析用に、外した曲の該当ノートの音声を切り出して保存する仕組みを最初から入れる。
  低音側の外れは耳で聞けば原因（ベース漏れ／フライ／フォール）が即分かるので、これが最も効率的なデバッグ手段になる

## 8. 日本語音名表記の変換

音域サイトは `mid2G#` / `hiA` / `hihiC` といったカラオケ表記を使う。**オクターブの境界が A** である点に注意
（C ではない）。対応表：

| 表記帯 | 範囲 | 例 |
|---|---|---|
| `lowlow` | A0 – G#1 | `lowlowB` = B1 |
| `low`    | A1 – G#2 | `lowF` = F2 |
| `mid1`   | A2 – G#3 | `mid1C` = C3 |
| `mid2`   | A3 – G#4 | `mid2C` = C4, `mid2G#` = G#4 |
| `hi`     | A4 – G#5 | `hiA` = A4, `hiC` = C5 |
| `hihi`   | A5 – G#6 | `hihiA` = A5 |

最低音は `low` / `lowlow` 帯に落ちることが多く、この帯はサイトによって表記揺れ（`lowlowA` を
別の書き方にする等）が出やすいので、**パーサは寛容に書き、パースできなかった表記はログに残して後で目視確認する**。
内部表現は **MIDI ノート番号（float, cents 保持）** に統一し、入出力でだけ変換する。

## 10. 進め方（推奨順）

| Phase | 内容 | 得られるもの |
|---|---|---|
| **0** | 分離（4stem）→ 2パス F0 → ノート化 → bass stem ブリード除去 → v0 ヒューリスティックまで一気通貫。参照ラベル 50 曲で 4 値を評価 | ベースライン数値。**ここで初めて問題の難しさが分かる** |
| **1** | 自己録音でシードデータ作成（フライ含む）、特徴量の分離性を検証 | 特徴設計の妥当性 |
| **2** | ラベリング UI + 能動学習で 50〜100 曲ラベル、v1/v2 学習 | 実用精度の本命 |
| **3** | ラベル収集を数千曲に拡大、MIL で v3 学習 | スケール |

**Phase 0 を飛ばさないこと。** 分離と F0 とノート化の品質が悪ければ、どんな分類器を載せても意味がない。
特に低音側は **bass stem 相互チェックを Phase 0 の時点で入れておく**こと。これが無いと低音のベースラインが
ノイズに埋もれ、その後の改善が測れなくなる。

逆に Phase 0 の時点でベースラインが ±2 半音に収まるなら、残りは分類器の勝負に絞れる。
経験的な難易度の予想は **地声最低音 < 裏声最高音 < 地声最高音 << 裏声最低音**（左が易しい）。
地声最高音が最難関なのは、ミックスボイスとの境界がラベル側でも曖昧だから。

## 11. 主要ライブラリ

| 用途 | 候補 |
|---|---|
| 音源分離 | `demucs` (htdemucs, 4stem) / `audio-separator` (BS-Roformer, MDX-Net) |
| F0 推定 | RMVPE（歌声に最も強い）/ `torchcrepe` / `librosa.pyin`（低域用） |
| 音響特徴 | `librosa`, `praat-parselmouth`(CPP/HNR/formant/harmonics), `opensauce-python` |
| SSL 埋め込み | `transformers` の WavLM / HuBERT、音楽なら MERT |
| 分類器 | `lightgbm`, `torch` |
| 保存 | SQLite / DuckDB + Parquet |
| UI | `streamlit` |
| 前処理 | `ffmpeg`, `yt-dlp`（入力経路の一つとして） |

処理時間の目安（GPU あり、1 曲 4 分）：分離 10–30s、F0（2パス）8s、特徴量 5s。
100 曲で 1 時間強。**学習より前処理が支配的**なので、キャッシュ設計が事実上の性能設計になる。
